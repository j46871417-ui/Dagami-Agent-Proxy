# Dagami Agent Proxy 0.3.6 альфа

Обновление после `v0.3.0-alpha`: шифрованный DNS Dagami → MagicDNS с обновлением
проверенных адресов из официальных профилей и локальной службой Windows,
обнаружение и проверяемая подготовка внешнего backend `%USERPROFILE%/.gemini/bin/agy.exe`,
упрощённая навигация Windows-клиента, команды диагностики CLI и уточнённая
проверка TLS/прокси.

## Что изменилось в 0.3.6

- **Шифрованный Smart DNS (Dagami → MagicDNS) и служба Windows.** Управляемые
  маршруты используют проверенные узлы DNS-over-HTTPS: сначала Dagami, затем
  MagicDNS. Приложение обновляет адреса из официальных профилей сервисов по
  HTTPS, проверяет кандидатов через DoH и сохраняет последний рабочий список.
  Кнопка «Включить в Windows» устанавливает локальную службу шифрованного DNS
  (`127.0.0.1` / `::1`) и правила NRPT; режим всей сети требует явного выбора
  адаптеров и подтверждения работы обоих семейств IPv4/IPv6. Пользовательский
  DNS остаётся отдельным и переключается с UDP на TCP при обрезке или сбое.
- **Системный DNS с несколькими проверенными узлами.** Начальный адрес по
  умолчанию обновлён на `45.147.31.32`. Перед применением каждый узел проходит
  проверку, недоступные исключаются до записи, а старые односерверные резервные
  копии остаются совместимыми для отката. Добавлена строгая проверка владения
  вопросом/ответом DNS, цепочек CNAME и коротких/нулевых TTL.
- **Внешний backend Antigravity в `.gemini/bin/agy.exe` и совместимый CLI.**
  Обнаружение и подготовка IDE/CLI учитывают загружаемый самой IDE файл
  `%USERPROFILE%/.gemini/bin/agy.exe` (в нативном клиенте и переносимом Python-адаптере).
  Для совместимых сборок x64 Antigravity CLI распознаётся локальная проверка
  доступности с сохранением исходного файла, проверкой SHA-256 при откате и
  отказом на неизвестных сигнатурах. Серверные проверки аккаунта, региона и
  подписки не изменяются.
- **Наглядная подготовка и упрощённый интерфейс.** В карточке приложения явно
  показано, подготовлен ли выбранный backend Antigravity, а настройка обычного
  запуска вынесена основным действием, пока не создан ярлык или CLI-команда.
  Навигация упрощена до разделов «Приложения», «DNS» и «Настройки» (диагностика,
  журнал, параметры запуска и системного DNS собраны во вкладках настроек).
- **Расширенная диагностика TLS, входа и CLI.** В диагностике TLS указываются
  целевой хост, уровень соединения и коды ошибок цепочки/политики сертификата
  без раскрытия субъектов сертификатов и без ослабления проверки. Диагностика
  входа показывает ошибки CONNECT внешнего прокси (например, HTTP 407) вместо
  общего кода 502 локального моста. В CLI добавлены команды `doctor`,
  `diagnose error`, предпросмотр `patch APP_ID --dry-run` и управление DNS
  (`dns refresh`, `dns enable`, `dns restore`).

Сохранены изменения `0.3.0` и `0.2.0`: поддержка структуры Antigravity IDE 2.6,
обнаружение MSIX Codex Desktop (`OpenAI.Codex`), локальная маршрутизация
ConnectRPC без утечки пароля прокси, баг-репорты с очищенным журналом и
картинкой, экспорт журнала в файл и интерактивная консоль CLI.

## Установка Windows

Закройте прежнюю копию Dagami в трее и распакуйте Windows ZIP в пустую папку.
Внутри один `DagamiAgentProxy.exe`; Python не нужен, требуется .NET Framework 4.8.
Профили и ключ активации остаются в пользовательском хранилище.

Нажмите «Найти приложения». Для настройки запуска через обычные ярлыки или
команду в PATH используйте «Настроить обычный запуск». Перед сменой маршрута
или подготовкой общего `agy.exe` полностью закройте IDE и CLI, а после
обновления CLI-команды откройте терминал заново.

**Откат заменяет ручные правки управляемых proxy-полей исходными значениями.**
Остальные настройки сохраняются. Неизвестные бинарные сигнатуры не изменяются.

## Проверки и ограничения

Проверены Windows-сборка, 124 Python-теста (2 пропуска), 21 нативный набор,
193 проверки `SystemDnsChecks.ps1` и 12 тестов сервиса на изолированных стендах
и loopback-трафике. Исполнитель нативных проверок требует явный отчёт `PASS`
от каждого набора. Реальные пользовательские настройки DNS, активация и
установленные бинарные файлы во время тестов не изменяются.

Это альфа. Серверные решения аккаунта, тарифа и доступности моделей зависят от
самого сервиса и прокси-маршрута. Полные живые сессии всех аккаунтов, моделей и
версий всех поддерживаемых IDE/CLI, а также окружения WSL/SSH/remote и
нестандартные пути профилей имеют отдельные ограничения. Готовых бинарников для
Linux/macOS нет: приложены архив исходников и инструкция сборки.
