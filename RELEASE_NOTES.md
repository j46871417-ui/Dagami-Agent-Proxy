# 🚀 Dagami Agent Proxy 0.4.0 beta

Обновление после [0.3.6 alpha](https://github.com/j46871417-ui/Dagami-Agent-Proxy/releases/tag/v0.3.6-alpha): доработаны вход и подготовка Antigravity IDE, управление маршрутами, закрытие фоновых процессов, откат и ручное добавление приложений.

## Приложения и интерфейс

- Отдельные флаги «Использовать прокси» и «Использовать Smart DNS» на главном экране, синхронизированные с настройками.
- Кнопка «Отменить патч», подробные статусы подготовки и переключатель автозапуска Windows на главном экране.
- Перед сменой маршрута Dagami предлагает закрыть активные сессии, показывает список приложений и предупреждает о несохранённых данных. При отмене или ошибке закрытия настройки остаются прежними.
- Закрываются также управляемые фоновые и дочерние процессы; проверяется фактический выход. Конфликты определяются по полному пути EXE, а не только по имени.
- В окне добавления объясняется поддержка выбранной программы. Повторный выбор EXE открывает существующую запись. Активную или настроенную запись нельзя удалить без остановки и отката.
- Исправлены размещение карточек, обрезка заголовков, контрастность окна активации и случайное переключение DNS/DPI колесиком мыши.

## Antigravity и вход

- Совместимые общие CLI/IDE backend получают локальный CLI-патч и полный набор из восьми известных protobuf-изменений. Старый частичный патч распознаётся и требует повторной подготовки.
- Исправлена обработка settings.json с UTF-8 BOM, мешавшим загрузке отдельной IDE.
- Поиск свежей OAuth-ссылки учитывает журналы обычной Antigravity и отдельной IDE; добавлен выбор Google-аккаунта и копирование ссылки.
- Исправлена обработка accounts.google.com. В DNS-only для него используется маршрут Windows.
- metadata.google.internal:80 получает локальный ответ 404 без длительного ожидания облачного endpoint.
- Добавлена опциональная блокировка известных запросов автообновления через мост и DNS-службу. После подготовки синхронизируются сопутствующие данные backend.
- GUI-сессии сохраняются при аварийном падении прокси; явная остановка сессии завершает её процессы.

## Маршрутизация и DNS

- Поддержан режим direct через обычную сеть Windows, включая системный VPN, в GUI, CLI и диагностике.
- При отказе Smart DNS до открытия туннеля возможен резерв через настроенный upstream. Отказавший upstream не заменяется молча прямым подключением.
- Выключенный прокси сохраняет свой адрес и реквизиты; его флаг учитывается диагностикой и CLI.
- Добавлены пресеты Comss.one, GeoHide, Malw.link и Xbox DNS, собственные DoH/DoT/UDP/TCP endpoints и импорт .mobileconfig.
- Добавлена ручная проверка DNS-узлов с доступностью и задержкой. Обновлены начальные адреса Dagami/MagicDNS, улучшены тайм-ауты, резервирование и обработка поздних ответов.
- Порядок по умолчанию — Dagami → MagicDNS. Другие провайдеры выбираются явно. Временно отложенные узлы сохраняются в резерве.
- Windows DNS-служба учитывает выбранный upstream, кэширует его настройки и поддерживает EDNS0 до 1232 байт.
- Расширены системные правила доменов Google/Antigravity; убрано слишком широкое правило microsoft.com. Доработана предварительная HTTPS-проверка.
- VPN/TUN-адаптеры отмечены отдельно и не выбираются автоматически для смены DNS всей сети.

## Патчинг, откат и права Windows

- GUI и CLI используют общий откат бинарного backend. Повреждённая копия и незавершённое восстановление больше не объявляются полным успехом.
- Восстановленный оригинал не считается активным патчем только из-за сохранённого манифеста. Неизвестные бинарные сигнатуры не изменяются.
- Неизвестным приложениям не записываются VS Code proxy-поля в произвольный JSON. Для них предусмотрен управляемый запуск и HTTP(S)-окружение.
- Исправлены определение GUI/CLI и разбор Node/npm-обёрток: пути из echo/комментариев не принимаются за entrypoint.
- Сохранение конфигурации выполняется через временный файл и замену; ошибки записи сообщаются, параметры подключения возвращаются к прежним значениям.
- Убрано постоянное требование запуска от администратора. Автозапуск использует обычные права; исправлена проверка XML задачи Планировщика.
- Добавлены контроль запуска с Low Integrity и команда --permissions-info. Программа объясняет ограничения сохранения файлов, не пытаясь исправлять их изменением прав пользовательских папок.

## Диагностика и производительность

- Проверяется действующий мост Dagami. Неудачная диагностика не блокирует сам запуск.
- userinfo → 401 без токена явно отделён от подтверждения входа, региона API и ответа модели. Добавлена диагностика VPN, Fake-IP и петли прокси.
- Работа моста ограничена 128 соединениями; перегрузка получает HTTP 503 вместо бесконтрольного роста обработчиков.
- Последовательно выполняются тяжёлые проверки backend; убраны лишнее хеширование в частом обновлении интерфейса и утечки Process-дескрипторов.
- Ускорен поиск сигнатур: на отдельной 32-МиБ фикстуре медиана снизилась с 34,47 до 9,84 мс. Это измерение алгоритма, не всего приложения.
- Добавлены ротация журнала после 2 МиБ и очистка устаревших временных данных обновлений/DNS-операций.
- Исправлены переносы строк и оформление баг-репорта.

## Экспериментальные функции

Добавлены режимы разделения TLS/TCP при отправке, DNS padding и подключение отдельно установленных winws.exe / goodbyedpi.exe. Эти режимы включаются отдельно и требуют проверки в конкретной сети. Внешние движки не входят в EXE Dagami. При загрузке старых настроек без явного выбора экспериментальное дробление и блокировка обновлений отключаются.

## Установка и обновление

1. Закройте прежний Dagami через трей → «Выход».
2. Распакуйте Windows ZIP в отдельную папку или скачайте DagamiAgentProxy.exe. Требуется .NET Framework 4.8; Python для Windows EXE не нужен.
3. Запустите новую копию. При ручной смене расположения Dagami повторно подготовьте нужные ярлыки/CLI-команды; после смены PATH полностью перезапустите терминал.
4. Если определяется прежний частичный патч CLI/IDE, выполните откат и повторную подготовку после закрытия использующих общий backend приложений.

**При откате ручные изменения управляемых proxy-полей заменяются исходными значениями. Остальные настройки сохраняются.**

## Проверки и ограничения

Проверены Windows-сборка, 25 нативных наборов, 124 Python-теста (2 пропуска), 6 тестов инструментов контроля исходников и упаковка. Проверки используют фикстуры, локальные процессы и loopback. Живой сценарий Antigravity подтверждён пользователем; живые аккаунты всех остальных продуктов не проверялись.

Бинарный патч применяется только к совместимому Antigravity. Локальный Smart DNS покрывает явный список Google/Antigravity, а не все домены любой добавленной программы. Остальные адреса используют выбранный прокси либо Windows. Программа, игнорирующая proxy-env, требует отдельного адаптера. Вход, подписки, квоты, регион API, WSL/SSH, контейнеры, daemon и нестандартные профили проверяются отдельно. Проверка сертификатов сохраняется.

Готовый бинарник публикуется для Windows. Для Linux/macOS приложены исходники и инструкции, без заявления о проверенных готовых сборках.
