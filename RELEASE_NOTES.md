# Dagami Agent Proxy 0.5.0 beta

Подробный список изменений относительно опубликованной 0.4.1 beta. В этом выпуске переработаны подключение к Dagami, интерфейс Windows и переносимые сборки для macOS и Linux.

## Подключение одним ключом из Telegram

- Команда `/key` в @bright26bot выдаёт ключ `DAGAMI1-…`. Вставьте его в окно активации или откройте «Подключение → Подключить по ключу».
- Клиент получает адрес шлюза через HTTPS, создаёт ключ устройства P-256, подтверждает доступ и выбирает общий маршрут. Вводить сервер, порт, логин и пароль для Dagami вручную больше не требуется.
- Ключ подключения действует 15 минут и привязывает одно устройство. Повторная попытка на том же устройстве возможна до истечения ключа. Предусмотрен лимит в три устройства на аккаунт.
- При сбое DNS клиент может подключиться к встроенному резервному IP шлюза. TLS-сертификат проверяется по имени сервера, подписи запросов также привязаны к имени.
- Проверки подписок и ограничений выполняет бот. В меню можно отозвать доступ устройств. Отзыв закрывает активные туннели управляемого шлюза.
- Прежняя привязка по ссылке поддерживается. Для старых версий офлайн-лицензия доступна через `/license` или кнопку «Ключ для старой версии».

## Свой прокси и общий маршрут

- На вкладке «Подключение» Windows постоянно доступны поле своего HTTP/HTTPS-прокси и кнопка «Использовать свой прокси».
- Можно указать `host:port`, полный URL с реквизитами или `direct` для маршрута Windows и системного VPN. Реквизиты скрываются при вводе и защищаются DPAPI при сохранении.
- Ручной адрес сохраняется отдельно от привязки Dagami. Переключение на Dagami сохраняет его для последующего использования. Несохранённый текст переживает переход между вкладками.
- Явное сохранение ручного маршрута включает прокси и отключает Smart DNS для этого маршрута. Ввод адреса сам по себе не переключает активные сессии.
- Кнопка «Использовать Dagami» возвращает к уже привязанному устройству. Для смены действующего маршрута программа проверяет активные сессии и предлагает завершить их.
- Один выбранный маршрут получают совместимые программы, запущенные из Dagami. В Windows он также используется настроенными ярлыками и командами CLI.
- В macOS и Linux свой HTTP-, HTTPS- или SOCKS5-прокси добавляется через «Подключение → Свой прокси».

## Нативный интерфейс

- Windows использует WinForms, macOS использует AppKit, Linux использует GTK 3. Настольное окно работает внутри процесса приложения.
- Добавлены системная, светлая и тёмная темы Windows.
- Основные разделы Windows доступны в боковой панели. Приложения, подключение, DNS и сброс, журнал и диагностика открываются напрямую.
- Ручной DNS и полный сброс DNS/NRPT находятся на странице DNS. Дублирующие действия настройки ярлыков объединены.
- В список Windows возвращены значки установленных EXE. Они извлекаются при фоновом поиске приложений и используются при отрисовке из памяти.
- Исправлено падение при закрытии меню темы щелчком снаружи. Уточнены состояния запуска, настройки и повреждённых ярлыков.
- Кнопки Telegram и проверки привязки показывают ход операции, ожидание подтверждения и ошибки в текущем окне.
- Выбор Gemini, Cursor, Codex, Claude или Antigravity перенесён в диагностику. Он задаёт адрес тестового запроса через общий маршрут.

## Запуск приложений и производительность

- Дополнены профили Gemini Desktop, Codex Desktop, Claude Desktop и Claude Code.
- Окно Windows появляется до завершения поиска приложений. Поиск приложений, извлечение значков и чтение состояния запуска выполняются в фоне.
- Обновления журнала поступают при открытом разделе журнала. Таймер состояния сессий используется при работающих приложениях и видимом окне.
- Изменения раскладки при переходах между разделами применяются группой. Сокращены повторные проверки файлов в обновлении интерфейса.
- Переносимый клиент и сборщик написаны на Go. Готовым настольным пакетам Python для запуска не требуется. Старые Python-исходники остаются в репозитории как миграционная база.
- Инспектор переносимого клиента читает бинарник блоками по 128 КиБ и ищет сигнатуры за один проход.

## Совместимость с 0.4.1 beta

- В Windows сохранены блокировка запуска при повреждённой конфигурации, проверка владельца локального TCP-соединения и лимит 128 активных соединений на мост.
- Сохранены проверка границ обычного HTTP, авторизация каждого нового соединения с внешним прокси, поддержка chunked RPC, trailers и 101 upgrades.
- Gemini Desktop использует отдельный мост через выбранный внешний прокси при включённом прокси. Конфликтующие Chromium/WebView2/Qt-флаги очищаются.
- Обновлятор проверяет версию и SHA-256, сохраняет резервную копию и запускает обновлённый файл после успешной установки и повторной проверки хеша. Защищённые каталоги требуют ручного обновления.

## Установка и пакеты

1. Завершите прежний Dagami через «Выход» в трее. Закройте приложения, для которых будете менять маршрут или обновлять ярлыки.
2. Для Windows скачайте отдельный `DagamiAgentProxy.exe` или `Dagami-Agent-Proxy-v0.5.0-beta-windows.zip`. При ручном обновлении используйте прежний путь EXE, чтобы настроенные ярлыки запускали новую копию.
3. Для подключения Dagami получите новый ключ через `/key` и вставьте его в приложение. Для своего прокси заполните поле на вкладке подключения.
4. После изменения CLI-запускателей и PATH полностью перезапустите терминал.

Вложения включают Windows EXE и ZIP, macOS для Intel и Apple Silicon, Linux для x64 и ARM64, архив исходников и `SHA256SUMS.txt`/`SHA256SUMS.json`. Windows ZIP содержит `SHA256-native.json` для встроенного обновлятора.

## Проверки и ограничения beta

- Выполнены Windows-проверки интерфейса, маршрутизации, защиты локального моста, HTTP/RPC, ярлыков, отката, активации устройств и обновлений. Проверки используют временные файлы, фикстуры и loopback.
- Тесты Go охватывают переносимый клиент и управляемый шлюз, включая подписи, повтор запросов, выдачу ключа, привязку и отзыв. Выполняются также тесты варианта маршрутизации и `go vet`.
- Пакеты macOS и Linux проверены кросс-компиляцией. Их интерфейс, системное хранилище и сетевые сценарии требуют проверки на соответствующих ОС. Изоляция локального моста по владельцу TCP-соединения проверяется для Windows-клиента.
- Пакеты выпущены без Authenticode и нотаризации macOS. Доступность входа, моделей и региональные ответы сервисов зависят от аккаунта, выбранного маршрута и самого сервиса.
- Программы, игнорирующие настройки прокси, требуют отдельного адаптера. WSL, SSH, контейнеры и удалённые процессы используют своё сетевое окружение.
- Прежний публичный вход 50128 временно обслуживает ранее выданные доступы на время перехода. Новый клиент использует управляемую привязку. Старые офлайн-лицензии продолжают приниматься для запуска прежнего сценария.
