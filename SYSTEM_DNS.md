# DNS в Windows

Для нового локального порта Linux/macOS: [режимы DNS и пределы проверки](PORTABLE.md#dns-и-откат).

По умолчанию Smart DNS создаёт правила NRPT для выбранных доменов.
DNS Wi-Fi, мобильной и рабочей сети при этом остаётся прежним.

Для смены DNS всей сети есть отдельный пункт и выбор адаптеров.
Адрес IPv4 меняет только DNS IPv4; адрес IPv6 — только DNS IPv6.
DNS второго семейства сохраняется. VMware обычно выбирать не нужно.

Перед записью приложение проверит доступ к DNS и HTTPS как минимум
на двух сайтах. Затем спросит новый сервер и проверит HTTPS через его
ответы, пока старый DNS ещё действует. Если проба не прошла, сеть не меняется.

После записи проверяются адреса DNS, правила NRPT и доступ к тем сайтам,
которые были доступны до неё. Для HTTPS нужен новый сеанс, без старого
соединения. При сбое идёт откат. Он возвращает DNS, режим DHCP/статики
и прежние правила NRPT. Далее сеть проверяется вновь.

Это проверка выбранных сайтов, а не гарантия доступа ко всем ресурсам.
У браузера может быть свой DNS, а у рабочей сети — свой прокси и свои имена.
Если их работа важна, оставьте общий DNS сети прежним и используйте NRPT.

Для ручного отката нажмите «Восстановить прежний DNS». Внешние правки
сохраняются, удалённые адаптеры пропускаются; все пропуски есть в отчёте.
Сбой самой команды отката не выдаётся за успех.

Копия: `%ProgramData%\DevProxy-SystemDns\state.json`.
Окна статуса читают копию без запрета на её замену. Если файл кратко
занят другим процессом, запись повторяется до трёх секунд с сохранением
атомарной замены. При долгой блокировке отчёт укажет имя файла;
прежняя копия не затирается и запись поверх открытого файла не делается.
Архив прошлой записи: `history-<ID>.json` в той же папке. Не удаляйте
копию для обхода ошибки. В итогах `Released` значит откат с пропусками.

Программа запрашивает права администратора при ручном запуске. Для
операции DNS повторный UAC не нужен, когда права уже выданы. Автозапуск
с правами и запуском в трей включается в «Подключение»; см. [порядок](STARTUP.md).
Помощник и его движок скрыты, итог показан в окне DNS.

В Windows нужен один `DagamiAgentProxy.exe`: GUI, CLI и помощник DNS
работают через него. Прямое окно DNS открывает команда
`DagamiAgentProxy.exe --dns-window`. Она не передаёт запуск старой копии
в трее и не меняет работающие сессии прокси. Окно использует иконку Dagami.

## Полный сброс DNS и NRPT

Красная кнопка «Очистить все DNS и NRPT…» — отдельный режим сброса.
Она дважды спросит: «Вы точно уверены в том что вы делаете?».
В обоих окнах по умолчанию выбран отказ. Любой отказ отменяет сброс
до запроса UAC и до записи в сеть.

Сброс задаёт авто DNS для IPv4 и IPv6 всех найденных адаптеров, в том
числе скрытых, отключённых, VPN и VMware, у которых есть настройки DNS.
Адаптеры без привязки DNS пропускаются с записью в отчёт; индекс такого
адаптера больше не прерывает сброс остальных. Списки и галочки в окне его
не ограничивают. Он удаляет все местные правила NRPT, включая чужие,
DNSSEC/DirectAccess и NRPT из местной копии политики, затем чистит кеш DNS.
Настройки DNS, заданные браузером, и файл hosts этот режим не меняет.
Сеть и рабочие имена могут стать недоступны. Авто DNS требует, чтобы
адреса DNS были выданы сетью. Правила из домена могут прийти вновь.

До первой записи весь снимок хранится в
`%ProgramData%\DevProxy-SystemDns\reset-<ID>\snapshot.json`.
Рядом лежат файлы `nrpt-0.reg` и `nrpt-1.reg` для тех ветвей NRPT,
которые были на ПК. В них сохранены все поля правил, включая DNSSEC.
Прежняя активная копия приложения остаётся в `history-<ID>.json`.
Если копия не создана, сброс не начинается. Для этого режима не нужен
рабочий DNS или доступ к сайтам до сброса.

Итог проверяется по DNS адаптеров, местным и активным NRPT. При сбое
одной из команд или возврате правил отчёт укажет частичный сброс.
Успех сброса означает сброс настроек, а не проверку доступа в интернет.

Пока сброс — последняя операция, кнопка «Восстановить прежний DNS»
вернёт его снимок. Новые внешние DNS будут пропущены с записью в отчёт.
Если после сброса появились новые NRPT, их возврат из копии будет
остановлен, чтобы не затереть новые правила. Копия останется для
ручного возврата. Новая запись DNS создаст свой снимок; старые копии
сброса остаются в папке ProgramData.
