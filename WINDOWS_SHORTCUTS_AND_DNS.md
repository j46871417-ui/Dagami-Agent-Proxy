# Обычные ярлыки и системный Smart DNS Windows

## Запуск приложения обычным ярлыком

1. В разделе «Приложения» выберите строку установленной программы.
2. Нажмите «Запускать через прокси из обычного ярлыка». Настраиваются только ярлыки текущего пользователя, у которых TargetPath соответствует выбранному EXE.
3. Открывайте программу привычным ярлыком. Если DevProxy закрыт, ярлык автоматически запустит его в фоне; локальный мост останется в трее.
4. Для отмены выберите ту же программу и выключите переключатель.

Сохраняются имя файла, значок, описание, горячая клавиша, исходные аргументы и рабочая папка. Windows уведомляется об обновлении `.lnk`. Поддерживаются обычные shell links на рабочем столе, в пользовательском меню «Пуск» и существующие `.lnk` закреплений панели задач. AppX/PWA-ссылки, прямой запуск EXE и системные ярлыки других пользователей этим режимом не перехватываются.

Копии и журнал находятся в `%APPDATA%\devproxy\shortcuts`. Копии проверяются SHA-256; журнал с исходными аргументами защищён Windows DPAPI CurrentUser. Запись журнала предшествует замене ярлыка. Перед откатом проверяются текущий и резервный хеши. Чужие правки не перезаписываются.

Аргументы ярлыка содержат только ID приложения и непрозрачный ID записи, без proxy credentials. Локальный IPC-канал и mutex привязаны к SID пользователя; сетевой доступ к pipe запрещён ACL. Повторная отправка запроса после потери подтверждения автоматически не выполняется. Один фоновый процесс управляет несколькими независимыми сессиями приложений.

Antigravity работает в обычном профиле, чтобы OAuth возвращался в ту же копию. Первый запуск через DevProxy требует закрыть ранее открытую напрямую Electron IDE: существующему процессу нельзя задним числом передать новое окружение. Следующие клики управляемых ярлыков используют уже созданную сессию. Дополнительные исходные аргументы передаются приложению, в том числе файлы и рабочие каталоги.

CLI нативной сборки:

```powershell
.\devproxy.exe --proxy-shortcuts antigravity
.\devproxy.exe --restore-shortcuts antigravity
```

## Системный DNS

Откройте «Подключение → Настроить DNS…». Здесь показаны активные адаптеры и их текущие DNS. По умолчанию указан IP `185.149.145.6` из пользовательского скрипта. Можно выбрать адаптеры, отключить изменение адаптеров, использовать только NRPT или наоборот.

Полный набор: 68 доменов `setup_smartdns_windows.ps1` и два уже поддерживаемых API Antigravity. Уменьшенный набор исключает перечисленные игры и стриминг. Это обычный системный DNS/NRPT; DoH данным режимом не настраивается.

При конфликте с прежними NRPT-правилами предварительная проверка останавливает применение до изменений. Для их замены отметьте «Заменить конфликтующие NRPT-правила с резервной копией». DNSSEC/DirectAccess/IPsec и многодоменные правила вне выбранного набора не заменяются автоматически. Незатронутые правила и адаптеры сохраняются.

Кнопки применения и отката запускают отдельный помощник этого же EXE с UAC. Основной интерфейс и proxy bridge продолжают работать с прежними правами. Скрипт извлекается из встроенного ресурса в защищённый каталог, проверяется и запускается системным Windows PowerShell без профиля и пользовательских путей модулей. Произвольные пути к скриптам и команды из интерфейса не принимаются.

Резервная копия: `%ProgramData%\DevProxy-SystemDns\state.json`. Каталог доступен на запись только Administrators и SYSTEM; пользователи имеют чтение. Отчёты операций — `jobs\<GUID>.json`. Сохраняются GUID и индекс адаптера, исходные DNS, отдельно DHCP/статика IPv4/IPv6, заменяемые NRPT-правила, созданные правила, этап применения и ошибки. Интерфейсные индексы сверяются с GUID перед применением; при откате адаптер ищется по GUID, в том числе после переименования.

При ошибке применения выполняется автоматический откат. Повторное применение не перезаписывает активную исходную копию: сначала требуется восстановление. Откат не перезаписывает последующие внешние изменения DNS/правил, а сообщает незавершённый результат. Предыдущие NRPT-правила восстанавливаются с исходными параметрами; Windows может назначить новый GUID правила.

Откат возвращает состояние **перед изменениями DevProxy**, а не до запуска других старых DNS-скриптов. Восстановление DHCP возвращает автоматический выбор DNS; адреса текущей DHCP-аренды могут отличаться от старых. Системный DNS сохраняется после выхода из DevProxy. Включение локального Smart DNS-маршрута в основном окне само по себе системные настройки не меняет.

## Проверки

- `ShortcutChecks.cs`: реальные временные `.lnk`, сохранение свойств, точный откат, защита правок и копий, DPAPI, IPC и повреждённый запрос.
- `SessionChecks.cs` + `FixtureApp.cs`: два временных приложения, дочерние процессы, исходные аргументы/рабочая папка, наследование всех proxy variables, повторный клик, закрытие в трей, отрисовка.
- `SystemDnsChecks.ps1`: DNS-команды заменены тестовыми реализациями; проверяются DHCP/статика IPv4/IPv6, NRPT, конфликты, частичный сбой и откат. Сеть компьютера этими тестами не меняется.
- `SystemDnsUiChecks.cs`: валидация запросов, встроенный ресурс, окно DNS без применения настроек.
- Существующие проверки NativeLoginChecks/NativeEofChecks сохраняют охват OAuth, TLS half-close и передачи через мост.

Сборка: `python build_native_app.py`. Для C#-проверок используется установленный .NET Framework `csc.exe`, ссылка `/reference:devproxy.exe` и необходимые System/Windows.Forms/Drawing-сборки. Запускайте проверки из каталога, содержащего `devproxy.exe`; DPAPI-тестам нужен загруженный пользовательский профиль Windows.

## Упрощённый интерфейс

Все действия относятся к одной выбранной строке приложения. Массовые флажки скрыты,
сохранённые CheckedIds не стираются. Основная кнопка открывает настройку подключения,
запускает приложение, активирует существующую сессию либо повторяет неудачную TCP-проверку.
Остановка сессии и удаление пользовательской записи требуют подтверждения. Удалить запись
с активной сессией или управляемыми ярлыками нельзя до их остановки/восстановления.

В меню «Ещё → Дополнительно» сохранены отдельные операции записи/восстановления настроек
выбранного приложения и восстановления обычных ярлыков. Восстановление одного приложения
не очищает общие переменные окружения Windows для других приложений.

При недоступности или повреждении журнала ярлыков переключатель блокируется с сообщением;
повреждённые и изменённые ссылки автоматически не перезаписываются. Проверка состояния
ярлыков выполняется без изменения файлов. Системный DNS не включается основной кнопкой.
