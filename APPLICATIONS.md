# Как добавлять и настраивать приложения

## Что означает «Пропатчить»

Dagami умеет три разных действия:

1. **Настроить запуск.** Обычный ярлык открывает приложение через Dagami,
   который работает в трее. Дочерним процессам передаётся локальный прокси.
   Для CLI вместо ярлыка может создаваться пользовательская команда в PATH.
2. **Изменить известные настройки.** Для семейства VS Code записываются
   управляемые proxy-поля в settings.json, для поддерживаемых JetBrains —
   proxy.settings.xml. До записи создаётся резервная копия. Для Codex Desktop,
   OpenCode и неизвестных программ произвольные JSON/TOML-файлы не изменяются.
3. **Подготовить совместимый backend Antigravity.** Только для распознанных
   сигнатур бинарника, с проверкой оригинала, резервной копией и точным откатом.
   Остальные программы не получают такой бинарный патч.

Настроенный запуск не подтверждает вход, подписку, квоту или ответ модели.

## Добавление

1. Нажмите «Добавить» и выберите исходный EXE или поддерживаемый файл CLI.
   Не выбирайте копию самого Dagami, установщик или уже созданный CLI-запускатель.
2. Проверьте описание возможностей в окне добавления. Имя в списке можно изменить.
   Повторный выбор того же EXE выбирает существующую запись, а не создаёт дубль.
3. Сохраните работу и закройте целевую программу, затем нажмите «Пропатчить».
   Если она ещё работает, Dagami предложит принудительное закрытие. Общий backend
   agy может использоваться одновременно IDE и CLI.
4. Открывайте настроенный обычный ярлык или команду CLI. После изменения PATH
   полностью перезапустите терминал. Прямой запуск исходного EXE может обходить
   параметры управляемого запуска.
5. Проверьте вход и короткий запрос. В диагностике 401 без токена проверяет
   доступность конкретного endpoint, а не генерацию.

## Если приложение неизвестно

Dagami создаёт управляемый ярлык и передаёт HTTP_PROXY / HTTPS_PROXY / NO_PROXY
дочернему процессу. Его EXE и собственная конфигурация остаются без изменений.
Если приложение поддерживает эти переменные, оно сможет использовать мост.
Если оно открывает сокеты напрямую или использует другую настройку прокси,
нужен отдельный адаптер. Это не универсальный перехват всего трафика Windows.

Известное имя EXE служит эвристикой выбора адаптера, а не подтверждением цифрового
издателя. Переименованные программы могут определиться иначе. Для семейства VS Code
учитывается portable-каталог data. Нестандартные профили, --user-data-dir,
idea.config.path, WSL/SSH/контейнеры и уже работающие daemon-процессы требуют
отдельной проверки: они могут использовать другой профиль или сетевое окружение.

## CLI и скрипты

- Native EXE запускается с исходными аргументами и окружением локального моста.
- Для распознаваемой Node/npm-обёртки определяется исходный entrypoint и Node.
  Произвольные CMD/BAT не исполняются через командную строку как универсальный fallback.
- PS1 запускается через Windows PowerShell без обхода системной политики выполнения.
- Системные команды cmd, powershell, pwsh, node и python не заменяются.
- Для Git создаётся отдельная команда dagami-git. Глобальный .gitconfig не меняется;
  SSH-транспорт отдельно не перенаправляется.
- Если системный PATH имеет приоритет, обычную команду нельзя надёжно заменить
  пользовательским PATH. Используйте запуск через Dagami; системный PATH не переписывается.

NODE_USE_ENV_PROXY зависит от версии Node и сетевой библиотеки. Официально переменная
есть с Node 24.0.0 и 22.21.0; её наличие в окружении не доказывает, что старая или
встроенная Node-сборка учитывает прокси: [документация Node](https://r2.nodejs.org/docs/v26.0.0/api/cli.html#node_use_env_proxy1).

## Выбор маршрута

| Флаги | Как идут запросы |
|---|---|
| Только прокси | Через выбранный внешний HTTP/HTTPS-прокси; локальные backend и OAuth callback исключены |
| Только Smart DNS | Известные Google-домены через Smart DNS; остальные через обычную сеть Windows |
| Прокси + Smart DNS | Основные Google/Antigravity-маршруты сначала используют Smart DNS; остальные адреса — прокси. Сбой Smart DNS до открытия туннеля допускает резерв через прокси. Это не последовательная цепочка двух сервисов |
| Оба выключены | Прокси-настройка не выбрана; интерфейс предлагает включить нужный режим |

Добавление Codex или Claude не добавляет автоматически все их домены в Smart DNS.
Для них может требоваться рабочий прокси или уже настроенный маршрут Windows.
Отказавший внешний прокси не заменяется молча прямым подключением.

## Откат и удаление

Нажмите «Отменить патч» перед удалением записи. Будут восстановлены управляемые
ярлыки/команда, известные настройки и принадлежащий Dagami бинарный патч Antigravity.
Ручные изменения управляемых proxy-полей заменяются исходными; остальные поля
сохраняются. Повреждённый backup или чужое изменение останавливает соответствующий
откат с явным сообщением. Частичный откат не объявляется полным успехом.

Работающую или ещё настроенную пользовательскую запись нельзя удалить, оставив
невидимый запускатель. После остановки и успешного отката запись можно удалить.
