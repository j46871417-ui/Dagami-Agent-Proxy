# Повторная проверка: Antigravity IDE 2.6 и интерфейс

Исправления включены в `v0.3.0-alpha` от 28.10.2026.

Дополнительно исправлено обнаружение Codex Desktop из MSIX: настоящий launcher
`app/ChatGPT.exe` читается из манифеста зарегистрированного `OpenAI.Codex`.
`CodexDiscoveryChecks` проверяет identity, выбор основного Application вместо
CLI helper, недопустимые пути/XML и обнаружение на текущей установленной копии
(только чтение, без запуска/остановки приложения). На машине проверки прошли
14 проверок. Обычный ChatGPT не присваивается записи Codex Desktop.

Изменения в исходниках после `v0.2.0-alpha` от 22.10.2026. Опубликованные ZIP и тег
этого выпуска не заменялись. Основание — пользовательский разбор
`Breakdown_IDE_2.6.md` от 28.10.2026, чтение текущего C#/Python и кода confeden.
Утверждения из разбора проверялись отдельно; сам документ не доказывает совместимость
с установленным клиентом и не задаёт инструкции исполнять сторонние патчи.

## Выявлено и исправлено

| Приоритет | Проблема | Изменение |
|---|---|---|
| P1 | `Antigravity IDE.exe` не распознавался; обычные пути запуска, сессии и подготовки обходили IDE | Отдельное обнаружение IDE рядом с Manager; единая проверка имени во всех нативных путях |
| P1 | Backend искался только в `resources/bin` и `extensions/antigravity/bin` | Добавлены `extensions/agy/bin` и внешний `%LOCALAPPDATA%/agy/bin/agy.exe`; отсутствие файла объясняется явно |
| P1 | Локальный ConnectRPC POST/CONNECT мог уходить во внешний прокси | Для буквальных loopback-адресов и localhost добавлен локальный маршрут; CSRF, auth, тело, chunks и trailers не переписываются |
| P1 | Адрес моста в `antigravity.serverUrl` создавал неверный маршрут/зацикливание | Проверка до записи настроек; блокировка обращения моста к самому себе. Правильный serverUrl сохраняется |
| P1 | Остановка моста не закрывала уже открытые туннели | Учёт и закрытие соединений при Dispose, в том числе после смены маршрута |
| P2 | Частичная подготовка нескольких backend могла выглядеть как полная | Отдельный признак Complete; предупреждение остаётся видимым |
| P2 | Галочка обычного запуска дублировала «Пропатчить», но выполняла лишь часть операции | Галочка заменена текстовым состоянием; настройка — одна явная операция |
| P2 | Повторялись баг-репорт в журнале, отдельное меню подготовки и пункты проверки прокси/ярлыков | Одна глобальная кнопка отчёта; подготовка/откат — в меню выбранного приложения; прокси проверяется в «Подключении» |
| P2 | Восстановление управляемых настроек и бинарника не требовало подтверждения | Подтверждение с безопасным ответом по умолчанию и предупреждением о ручных правках/общем agy |
| P2 | README всё ещё называл опубликованные изменения «не опубликованной альфой 10» | Исправлены статусы, пути и инструкции; старый релиз отделён от текущих исходников |

В Python добавлены обнаружение нового Windows EXE/профиля и такой же локальный
маршрут. Удалённые HTTPS-соединения по-прежнему идут через выбранный upstream;
произвольные имена, LAN-адреса и ошибки upstream не включают прямой обход в интернет.
Сертификаты проверяются. Proxy-Authorization удаляется только на локальном маршруте;
пользовательский Authorization и x-codeium-csrf-token сохраняются.

## Что из разбора не нужно копировать из confeden

Dagami не патчит `extension.js`/`out/main.js` и не использует регулярку
`UserStatus.getUserStatus()`. Ошибки этих JS-патчей в confeden не являются
воспроизведёнными ошибками Dagami. Для ConnectRPC v2 нужен корректный транспорт,
а не подмена статуса пользователя, тарифа или CSRF. Неподтверждённые бинарные
сигнатуры, как и раньше, не изменяются.

## Проверки

- Python: полный `unittest discover -s tests -p 'test_*.py'`, включая новые IDE/RPC
  сценарии и тесты сохранения прочих настроек/упаковки.
- Native: безопасные наборы из `tools/run_native_checks.py`. Новый `Ide26Checks`
  проверяет обе формы HTTP-запроса, локальный CONNECT, IPv4/IPv6, потоковый ответ
  с trailers, сохранность CSRF/auth, отсутствие proxy-пароля и закрытие старого маршрута.
- `AntigravityPatchChecks`, `PatchChecks`, `ShortcutChecks`, `ReviewRegressionChecks`
  проверяют совместимость прежних форматов, идемпотентность и точный откат на fixtures.
- `LocalUiChecks`: реальные WinForms-скриншоты и границы контролов на стандартном
  и минимальном размере окна, включая диалог баг-репорта. Для статического preview
  остановлен фоновый polling; ошибки UI пробрасываются в результат теста.
- Сборка EXE, source ZIP, source-policy и проверка diff; реальные DNS, активация
  и установленные чужие бинарники не меняются ради тестов.

## Границы и следующие проверки

На машине проверки установлен `Antigravity.exe`; именно IDE 2.6 с новым плагином
и действующим аккаунтом не была доступна. Новая структура, settings и RPC
проверены на изолированных fixtures. Это не проверка входа, прав аккаунта,
моделей и стриминга конкретного официального клиента. Нужен отдельный живой прогон.

Профиль `Antigravity IDE` соответствует имени приложения из предоставленного
разбора; явный пользовательский путь и portable-профиль сохраняются. Если сборка
IDE задаёт другой user-data-dir, нужно выбрать её реальный settings.json.

После смены имени/каталога IDE нужно заново настроить её ярлыки. Старые записи
другого приложения автоматически не присваиваются новой IDE. Общий внешний agy
следует закрыть перед запуском с новым окружением; уже работающий daemon не
получает переменные задним числом. Автоматическая миграция всех профилей,
полное покрытие DPI/тем и реальные сессии всех остальных IDE не подтверждены.

Справка по стандартному месту установки CLI:
[официальная инструкция Antigravity](https://www.antigravity.google/docs/getting-started?tab=cli).
Структура сторонних патчей сравнивалась с
[confeden/Antigravity](https://github.com/confeden/Antigravity); сторонний код
не исполнялся и его авторизационные подмены не переносились.

## Дополнение: пять пользовательских журналов предыдущей версии

Исходные журналы не включаются в Git и архивы. Это усечённые файлы примерно по
64 КиБ; часть начинается посреди записи. Число записей не равно числу пользователей
или независимых сбоев. Адреса прокси, контакты и авторизационные данные здесь
не воспроизводятся.

| Наблюдение | Вывод и действие |
|---|---|
| В двух файлах 99 и 214 ответов CONNECT 407 | Внешний прокси отклоняет авторизацию. Проверка одного TCP-порта могла показывать успех. Добавлена прямая проверка CONNECT с корректным сообщением о логине/пароле/доступе у провайдера; Smart DNS её не обходит |
| CONNECT 403 и 503 | Отказ получен от прокси до TLS с целевым сервисом. Это не HTTP-ответ аккаунта или модели Google; добавлено различение уровня ошибки |
| Повторное «Не удалось привязать порт моста» | Точная причина старых отказов без SocketError не доказана. После десяти предпочтительных портов теперь запрашивается свободный порт Windows; добавлены закрытие неудачных listener, защита от self-upstream и причина полного отказа |
| 127 тайм-аутов чтения без входящих байтов на OAuth через Smart DNS в одном файле | Проверка userinfo недостаточна для отдельного token endpoint. При неудаче синтетического POST /token сравнивается второй маршрут во временном мосте; реальные коды/токены не читаются и не повторяются, настройки автоматически не меняются |
| NullReferenceException сразу после диагностики | В старой реализации воспроизводится ошибка поиска сессии при пустом ExePath другого приложения. Текущий IsIde безопасен для null; добавлен регрессионный сценарий. Старый журнал не содержит стека, поэтому точное совпадение причины не утверждается; новый UI-журнал сохраняет очищенный тип/стек и имя действия |
| Неизвестные protobuf-сигнатуры | Защитный пропуск, а не доказательство успешного патча. По одному SHA-256 невозможно разработать совместимый бинарный патч; файл остаётся неизменным, предупреждение сохраняется |
| Отказ preflight системного DNS | Защитная проверка не подтвердила HTTPS через новый DNS; по журналу настройки сети не записывались. Эта защита не отключается |
| Две ошибки загрузки обновления InvalidDataException без причины | Старых данных недостаточно для диагноза. В журнал добавлена очищенная причина исключения; проверки SHA-256, версии и принадлежности архива сохранены |

Дополнительный `ProxyFailureChecks` проверяет 200/407/403/503 на собственном
loopback-прокси, кодирование тестовых credentials, отсутствие прикладных данных
после CONNECT, отказ неправильных URL, занятые десять портов, self-upstream и
сравнение синтетических OAuth-запросов. Чужие прокси из логов для тестов не используются.
