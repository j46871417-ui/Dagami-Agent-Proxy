# Баг-репорты в 0.2.0 альфа

С разрешения владельца 22.10.2026 система размещена на dns.dagami.ru. Проверены
форма, закрытая панель и отправка из Windows EXE по HTTPS с журналом/картинкой.
GitHub, релизы программы и DNS не менялись. Это не готовый публичный релиз всей программы.

## Windows

«Баг-репорт» в основной навигации или «Журнал → Сообщить об ошибке»:
заголовок, описание, необязательный контакт. «Журнал → Сохранить в файл…»
открывает стандартный выбор файла и сохраняет очищенный видимый журнал в UTF-8.
Последние 64 КиБ журнала очищаются и прикладываются автоматически. Можно просмотреть
текст и добавить одну PNG/JPEG до 2 МиБ / 12 мегапикселей. Картинка показывается
перед отправкой; её содержимое пользователь проверяет сам. EXIF и прочие метаданные
удаляются. Скриншоты автоматически не снимаются. Отправка начинается только кнопкой.

Удаляются известные форматы proxy URL, Authorization, cookie, токенов, паролей,
ключей активации, e-mail и имени в стандартных пользовательских путях. Это фильтр
известных форматов, а не гарантия обнаружения любых персональных данных. Контакт
в отдельном поле сохраняется намеренно. Файлы конфигурации, код и профили не собираются.

Перед запросом точный payload сохраняется через Windows DPAPI CurrentUser в
`%LOCALAPPDATA%\DagamiAgentProxy\reports\<UUID>.pending`. До 20 неотправленных отчётов.
Повторная отправка сохраняет UUID и ключ квитанции: потерянный ответ сервера не создаёт
дубликат. «Повторить неотправленные» обрабатывает очередь после перезапуска программы.
После успеха остаётся DPAPI-квитанция `.receipt`, журнал и картинка из очереди удаляются.
HTTP разрешён только для loopback-тестов; рабочий адрес HTTPS, редиректы запрещены,
сертификаты проверяются, upstream-прокси с паролем не используется для отчёта.
Новый интерфейс отчётов относится к основной нативной Windows-сборке.

## Сайт и API

- `/support/agent-proxy/`: форма с журналом-файлом и картинкой, выдача/загрузка
  квитанции, проверка статуса своего обращения.
- `/support/agent-proxy/admin/`: только через SSH-туннель; вход, фильтр/страницы по 50,
  описание/контакт/журнал/картинка, скачивание журнала, смена статуса, выход.
- `/api/bug-reports/v1/reports`: POST JSON с `id`, `receipt_token`, `title`,
  `description`, `contact`, `version`, `platform`, `logs`, `image_base64`.
- GET `/reports/<id>`: только статус, с `Authorization: Bearer <receipt_token>`.
- `/admin/login`, `/admin/session`, `/admin/logout`, `/admin/reports`,
  `/admin/reports/<id>`, `/admin/reports/<id>/image`, `/admin/reports/<id>/status`.

UUID не является паролем: без сессии администратора журналы и картинки недоступны.
Ключ квитанции хранится на сервере как SHA-256 и даёт только статус. Админский пароль
хешируется PBKDF2-HMAC-SHA256 (600000 итераций); общего ключа в EXE/JS нет.
Сессии на 8 часов, HttpOnly/SameSite=Strict, защита CSRF для изменения статуса
и выхода, ограничение перебора и частоты отправки. Админка обслуживается только на
loopback HTTP через SSH; SSH шифрует соединение до сервера. Публичные admin URL/API
возвращают 404. В приватном интерфейсе cookie не имеет Secure, поскольку адрес
локальный HTTP; публичных admin-сессий нет. После перезапуска службы нужен вход.

Сервис — отдельный пользователь, loopback 3091, SQLite WAL в закрытом StateDirectory.
JSON до 3 МиБ; журнал до 65536 символов; картинка PNG/JPEG до 2 МиБ/12 Мп,
декодирование и пересоздание пикселей без метаданных, до двух запросов одновременно.
SVG/HTML и неправильные файлы отвергаются. Не более 5000 отчётов и 512 МиБ содержимого;
при заполнении сервис возвращает ошибку, очередь в программе остаётся.
Журналы HTTP не содержат тела/контакты/ключи; API возвращает `no-store` и `nosniff`.
HTML пользователя выводится как текст.

Ежедневная служба делает online SQLite backup до очистки, удаляет отчёты старше
90 дней и оставляет снимки за 3 дня. Данные удалённого обращения могут оставаться
в этих снимках до следующей очистки резервных копий; сроки зависят от работы timer.
Для переноса/восстановления использовать SQLite backup, а не копирование одного
`.sqlite` при активном WAL. Отправка уведомлений другим людям не добавлена.

## Исходники сайта

Сервис, тесты, systemd units, шаблон nginx и статические страницы находятся в
[bug_reports/](bug_reports/README.md). Они устанавливаются отдельно от программы.
На dns.dagami.ru сервис уже работает; пользователю приложения разворачивать его
не нужно. Секреты, база, снимки и учётные данные администратора в Git не включены.

При развёртывании исправлена гонка подтверждения статуса: ответ отправляется только
после commit SQLite; добавлен тест с задержкой commit. Для .NET Framework 4 явно
включён TLS 1.2 без отключения проверки сертификатов. Оба исправления проверены.
