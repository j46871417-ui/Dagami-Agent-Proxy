# Dagami Agent Proxy

Менеджер запуска IDE и CLI через свой прокси. Профили, запуск приложений,
ярлыки, системный DNS с копией и откатом. Ранее — DevProxy.

**[Скачать v0.2.0-alpha](https://github.com/j46871417-ui/Dagami-Agent-Proxy/releases/tag/v0.2.0-alpha)**
· **[Собрать Linux / macOS](BUILD_LINUX_MACOS.md)**

Предварительная версия 0.2.0: исправления ярлыков и CLI-консоли, подготовка
приложений и баг-репорты с журналом/картинкой. [Изменения и ограничения](RELEASE_NOTES.md).

## Что есть в выпуске

| ОС | Что доступно | Статус |
|---|---|---|
| Windows | ZIP с одним `DagamiAgentProxy.exe` | Сборка и локальные тесты выполнены |
| Linux | Код, GUI/CLI, сессии, DNS NM, автозапуск и план сборки | Готового бинарника нет; нужны пробы на Linux |
| macOS | Код, GUI/CLI, сессии, DNS, автозапуск и план сборки | Готового `.app` нет; нужны пробы и подпись на Mac |

Файлы `dagami-proxy.exe` и `DagamiDns.exe` больше не нужны. Один главный
файл служит для GUI, CLI, окна DNS и запроса прав. Ключи и готовые файлы
сборок не хранятся в Git. [Правила исходников](SOURCE_POLICY.md).

## Windows: запуск и смена версии

1. Скачайте Windows ZIP из выпуска. Python для него не нужен; нужен
   .NET Framework 4.8, штатный для новых Windows 10/11.
2. Закройте прежнюю копию в трее. Распакуйте новый ZIP **в пустую папку**.
3. Запустите `DagamiAgentProxy.exe` и подтвердите права ОС.
4. Выберите профиль и приложение. Перед сменой маршрута полностью
   закройте само приложение; уже открытый процесс не получит новое окружение.

Прежние профили и ключ активации остаются в хранилище пользователя.
Ключ берётся в [@bright26bot](https://t.me/bright26bot?start=dagami).
Обычная команда CLI также идёт через один файл:

```powershell
.\DagamiAgentProxy.exe --help
.\DagamiAgentProxy.exe --dns-window
```

В «Подключение» можно включить вход в Windows с запуском в трей и правами
админа. Пароль учётной записи не сохраняется. [Автозапуск](STARTUP.md).
Кнопка «Пропатчить» для CLI задаёт обычную команду в PATH пользователя.
После смены команды полностью откройте терминал заново.

## DNS и сеть

По умолчанию Smart DNS задаёт лишь правила доменов. Общий DNS сети
меняется отдельным пунктом с выбором нужных подключений.
До и после записи есть пробы DNS и HTTPS. Ошибка вызывает откат;
отчёт отдельно укажет, если доступ к сети после отката не подтверждён.
Чужие правки сохраняются, удалённые подключения пропускаются.

Красная кнопка полного сброса охватывает и чужие DNS/NRPT в Windows.
Она задаёт два вопроса «Вы точно уверены в том что вы делаете?».
До записи хранится копия. Сброс может лишить сеть рабочих имён;
он не служит пробой сборки. [Режимы DNS и возврат](SYSTEM_DNS.md).

## Linux и macOS: сборка самим пользователем

Скачайте архив исходников из того же выпуска либо клонируйте тег.
Собирать нужно на самой ОС и её архитектуре, от обычного пользователя.

**[Полный план с командами для Linux и macOS](BUILD_LINUX_MACOS.md)**

На Linux результат — один `dagami-agent-proxy`, на macOS — один
`Dagami Agent Proxy.app` с главным файлом и ресурсами внутри. GUI и CLI
используют тот же файл. Права для DNS запрашиваются отдельно.

Linux: общий DNS через NetworkManager; домены требуют уже включённый
dnsmasq. macOS: службы networksetup и файлы resolver. Свои службы VPN
и иной менеджер DNS могут быть вне этих путей. Эти режимы ещё не прошли
наши живые пробы на целевых ОС. Windows-обновлятор и окно активации
пока не перенесены. [Методы, копии и пределы](PORTABLE.md).

## Приложения и пароли

### Локальная доработка альфы 10 (не опубликована)

Откат настроек IDE возвращает исходные значения прокси из копии. **Ручные изменения
этих прокси-ключей, сделанные после применения, будут заменены.** Остальные ключи
конфига сохраняются. Если копии нет, восстановление удаляет прокси-ключи, включая
введённые вручную. Это ожидаемый режим полного сброса настроек приложения.
Он не меняет отдельные правила восстановления системного DNS и бинарных файлов.

«Пропатчить» и «Ещё → Найти или создать ярлык» восстанавливают настройку после
удаления/переноса ярлыка или его пересоздания установщиком. Старый журнал хранится
в каталоге `shortcuts/history`; исходные копии остаются. При совпадении имени с
чужим ярлыком выбирается свободное имя. Перенос самого Dagami учитывается при
повторном патче. Ярлык другого приложения автоматически не перезаписывается.

Подготовка Antigravity работает с `resources/bin/language_server*.exe`, backend
IDE в `resources/app/extensions/antigravity/bin` и непосредственно с `agy.exe`.
Поддержанные protobuf-метаданные меняются с сохранением длины файла; при наличии
подходящего литерала `https_proxy` он заменяется на `AG_LS_PROXY`, который уже
передаётся управляемому процессу. Сохраняются оригинал, манифест SHA-256 и история
копий предыдущих обновлений. Проверка/повторное применение выполняются перед
управляемым запуском, отдельная служба наблюдения не устанавливается.
Неизвестные, смешанные и неподтверждённые состояния не изменяются.
Уже подготовленный прежней версией файл не переписывается. Он продолжает получать
`HTTPS_PROXY` при управляемом запуске; для перехода на отдельную `AG_LS_PROXY`
сначала отмените бинарную подготовку, затем примените её снова.

В разделе «Antigravity» операции выполняются для выбранного совместимого клиента;
если выбран другой тип приложения, используется первый найденный Antigravity.
«Подготовить клиент» и «Отменить подготовку» доступны в меню «Дополнительно…».
Подготовка не подтверждает доступ аккаунта к моделям. Настройки прокси и ярлыков
можно применять независимо от совместимости бинарного патча.

Баг-репорты: «Журнал → Сообщить об ошибке». Очищенный журнал прикладывается
автоматически, PNG/JPEG — по выбору. При сбое сети сохраняется зашифрованная очередь.
API и закрытая панель размещены на dns.dagami.ru с разрешения владельца 22.10.2026.
Проверена отправка из Windows EXE через HTTPS, в том числе лога и картинки.
Кнопка «Баг-репорт» есть в основной навигации и доступна с любого экрана.
В «Журнале» кнопка «Сохранить в файл…» предлагает выбрать папку и имя файла;
экспортируется очищенный видимый журнал в UTF-8. Панель администратора сайта
доступна только через SSH-туннель. Подробности: [BUG_REPORTS.md](BUG_REPORTS.md).
Фоновой отправки без нажатия кнопки нет.

Добавлена отдельная подготовка IDE семейства VS Code, Codex Desktop/CLI,
OpenCode Desktop/CLI, Gemini CLI, Claude Code, Git и JetBrains. PowerShell/cmd
из автоматического поиска удалены; ручное добавление и откат старых настроек доступны.
Для Git создаётся команда `dagami-git`; для JetBrains используется штатный XML.
Механизмы и ограничения: [MATRIX.md](MATRIX.md), структуры и источники:
[APPS_RESEARCH.md](APPS_RESEARCH.md), повторная проверка и оставшиеся доработки:
[RECHECK_20261022.md](RECHECK_20261022.md). Поддержка конкретной версии,
вход в аккаунт и доступ к моделям проверяются в самом приложении.
Неизвестный бинарный патч не применяется; у прокси и ярлыков свой путь.

Пароли хранятся в средствах ОС. Если Secret Service или Keychain закрыт,
сохранение пароля в открытый файл не допускается. Логи ограничены
по размеру; вывод приложений с токенами не пишется в журнал сессии.

Сборки: `python tools/build_native_app.py` на Windows;
`python tools/build_portable.py` на Linux/macOS после установки зависимостей.
Скрипты сами не загружают и не публикуют файлы.

Нативные исходники, manifest и DNS-ресурс находятся в `src/`, скрипты сборки и
установки — в `tools/`. Правила работы: [AGENTS.md](AGENTS.md), история изменений:
[CHANGELOG.md](CHANGELOG.md). `.agents/` содержит проектные инструкции и пустые
шаблоны hooks/MCP; автоматические внешние подключения не включены.
