# Нативные настольные сборки Dagami Agent Proxy

## Какую сборку открыть

- **Windows:** основной `Dagami-Desktop-windows-amd64.zip` и отдельный
  `windows-native/DagamiAgentProxy.exe` с WinForms. Сохранены прямые разделы
  «Приложения», «Подключение», «DNS и сброс», «Журнал» и «Диагностика».
  Ручной DNS и сброс NRPT доступны на странице DNS.
- **macOS и Linux:** `Dagami-Portable-<система>-<архитектура>.zip`. Окно
  использует системные контролы AppKit на macOS или GTK 3 на Linux.
- **Только маршрутизация:** `Dagami-Routing-<система>-<архитектура>.zip`.
  Использует Win32, AppKit или GTK 3. В этот пакет входят профили, запуск
  приложений и диагностика связи. См. [APP_ROUTING.md](APP_ROUTING.md).

Настольное окно работает в процессе программы. Локальный loopback-порт
используется как прокси для запускаемых программ. Интерфейс обращается к
настройкам и операциям напрямую внутри процесса.

## Платформы и функции

WinForms использует .NET Framework 4.x, установленный в Windows. На Linux
для окна нужен GTK 3 (`libgtk-3.so.0`). Для сохранения секретов нужен
`secret-tool` и работающий Secret Service, для ручного DNS — systemd-resolved
и polkit. На macOS интерфейс использует системный AppKit и Keychain. Сборки
macOS и Linux проверены кросс-компиляцией. macOS-пакет не подписан Developer ID.

| Возможность | Переносимый клиент |
| --- | --- |
| Профили, запуск приложений, CLI, сессии и журнал | Go, нативное окно |
| HTTP/HTTPS/SOCKS5, ограничение соединений, повтор CONNECT | Go |
| Проверка TLS и HTTP по сервисам | Go, прямой вызов транспорта профиля |
| Ручной DNS и восстановление | Адаптеры ОС, Windows использует существующий PowerShell-движок |
| Полный сброс DNS и NRPT | Windows, два подтверждения и резервная копия |
| Инспекция backend и SHA-256 | Чтение порциями по 128 КиБ и поиск сигнатур в одном проходе |

У переносимого клиента отдельный каталог настроек `DagamiAgentProxy/native-v1`.
Он использует DPAPI, Keychain или Secret Service для реквизитов прокси.
WinForms использует прежний каталог `devproxy` и сохраняет ярлыки, патчи и
Windows-службу DNS. У каждой сборки свои настройки и параметры командной строки.

## Сборка

В корне проекта с Go 1.23+:

```text
go run ./cmd/dagami-build -target all -test -source
```

На Windows основной архив автоматически собирается с .NET Framework.
`-windows-native -native-checks` дополнительно сохраняет EXE и проверяет
WinForms. С хоста macOS или Linux цель Windows кросс-компилирует клиент Win32.
Результаты и SHA-256 сохраняются в `dist-portable/native-next`.

Переносимый клиент принимает `-preview` для локального окна без изменений,
`-doctor` для JSON-снимка и `inspect-binary PATH` для чтения сигнатур.
Команда `DagamiAgentProxy run codex -- --help` запускает зарегистрированный
CLI через активный профиль. На Windows в PowerShell укажите `.\DagamiAgentProxy.exe`,
на macOS и Linux — путь к исполняемому файлу.

## Что взяли из источников

- [Dagami mac.28](https://github.com/ImRealDerli/Dagami-Agent-Proxy-macOS/releases/tag/v0.4.1-mac.28-beta): ограниченный транспорт, двухсторонняя передача,
  сохранение TLS и один повтор CONNECT до передачи данных. В интерфейсе —
  компактные карточки и отдельные профили с понятным состоянием.
- [confeden 2.28.2](https://github.com/confeden/Antigravity/releases/tag/v2.28.2):
  явно показывать состояние backend и учитывать внешний `.gemini/bin/agy`.
  Успешная проверка маршрута не выдаётся за ответ модели. Пулы чужих прокси
  и код проекта не включены.
- [Open AG Patcher](https://github.com/trustybird/AvenCores-open-antigravity-patcher):
  отличать локальный патч от серверного отказа. Код GPL не заимствован.

Переключения в DNS и патчи на живых приложениях при проверке не запускались.
Производительность реальной модели и выходов VPN зависит от сети; результаты
loopback-тестов не подтверждают скорость или доступность аккаунта.
