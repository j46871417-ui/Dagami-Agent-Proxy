# Независимый резерв и закрытый пул выходов

Серверные компоненты; новая версия приложения для их использования не нужна.
Приложение использует прежний подписанный вход Dagami. URL, логин и пароль
поставщика не выдаются клиенту ни в конфигурации, ни в ответах API.
Выходной IP виден внешним сайтам и может быть определён пользователем.

## Компоненты

- `cmd/dagami-reserve`: самостоятельный TLS-шлюз для существующих устройств
  либо loopback CONNECT-брокер за действующим контроллером/учётом трафика.
- `export_snapshot.py`: принудительная SSH-команда на основном узле. Выдаёт
  только привязки устройств и политику; не выдаёт ключи доступа, пароли,
  хеши паролей или токен Telegram. Учитывает действующий allowlist контроллера.
- `sync_snapshot.py`: root-служба на резерве. Отдельный SSH-ключ допускает
  только экспорт, только с разрешённых IP, без PTY, agent/X11/port forwarding.
  Период 5 секунд, атомарный файл root:gateway 0640. Приватный Unix-сокет
  обновляет снимок после регистрации через основной шлюз.
- `pool_admin.py`: панель владельца на **127.0.0.1:18995**. Только SSH-туннель,
  пароль панели, сессионная cookie, CSRF/Host/Origin проверки, без журналирования
  запросов. Не публиковать через сайт/прокси и не открывать порт в firewall.
- `export_pool.py`, `mirror_pool.py`: отдельный ограниченный SSH-ключ переносит
  реквизиты только между серверами. Основной выход получает каталог каждые
  10 секунд, пользователи его не скачивают. Русский узел не передаёт данные прокси.

## Панель владельца

Добавить название и готовый URL либо протокол, сервер, порт, логин, пароль
отдельно. Поддержаны HTTP CONNECT, HTTPS, SOCKS4/4a, SOCKS5/5h и SOCKS5 over TLS.
Поле «HTTPS» означает TLS до самого прокси; HTTP-прокси с поддержкой HTTPS-сайтов
обычно задаётся как **http**, уточняйте формат у поставщика.

Указать число дней или дату/время Екатеринбурга (UTC+5). Пустой срок означает
бессрочно. В хранилище даты приведены к UTC. Доступны выключение, включение,
удаление, смена срока и приоритет приватных прокси.
Приватный пул используется только после проверки отдельной подписи ключевого
режима. Обычный режим Dagami не использует его неявно. Публичные прокси
в приложении доступны отдельно, без ключа, и не смешиваются с этим инвентарём.
В панели не отображаются сохранённые адреса и пароли; замена реквизитов —
удалить запись и добавить новую. Не передавать реквизиты через Telegram/логи.

Список публикуется в приватный `routes.json` и подхватывается раз в секунду.
Истечение срока исключает маршрут независимо от доступности центрального
каталога. Панель также удаляет просроченную запись с реквизитами из SQLite.
Удаление/выключение/истечение закрывает активные соединения этого выхода;
изменение приоритета влияет на новые подключения.

Новые выходы допускаются только после двух успешных HTTPS-проверок. Проверки
каждые 20 секунд разделены на Google, OpenAI и общий интернет; используются
проверенные сертификаты и ожидаемые HTTP-статусы. Две ошибки исключают выход,
две успешные проверки возвращают его. У платного выхода дополнительно
проверяется страна внешнего IP через HTTPS Cloudflare; RU/неизвестные страны
не допускаются. Это геолокация IP, а не доказательство физического маршрута.
Проверки без аккаунта не доказывают, что конкретный аккаунт получит ответ модели.

## Резерв авторизации

Действующие устройства работают с последним корректным снимком при отказе
основного узла. Неизвестное устройство доступа не получает. Новые активации
проходят через основной шлюз; при его полном отказе временно недоступны.
Снимок не превращает краткую аренду контроллера в срок действия ключа.

**Компромисс:** при разрыве синхронизации отзыв/изменение прав приходит на
резерв после восстановления связи. Автоматического произвольного срока
истечения всех выданных ключей нет. Для немедленного прекращения доступа
во время изоляции нужно остановить резерв на нём самом.

Счётчики основного контроллера/traffic meter сохранены. Резерв пишет отдельные
совокупные счётчики; их агрегация в Telegram-статистику пока не реализована.
Закрытые пользовательские данные и per-user logs не синхронизируются.

## Развёртывание и проверка

Собирать `CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o dagami-reserve ./cmd/dagami-reserve`.
Сначала отдельные непривилегированные пользователи gateway и inventory,
приватные каталоги 0750; SQLite/пароль панели 0600, routes/health 0640.
Root SSH-ключи и pinned known_hosts — в root-only каталоге 0700.
Секрет Basic существующего брокера передавать через systemd LoadCredential.
TLS шлюза тоже через LoadCredential; после обновления сертификата перезапустить
резерв с актуальными credentials. Не переносить TLS-ключи в репозиторий.

До переключения Nginx/HAProxy проверить закрытый listener и существующее
устройство. Сохранять конфиги, SHA256, имя службы и команды отката. Проверять
изолированный резерв запретом связи **только его UID** с основным узлом и
паузой синхронизации, с заранее взведённым автоматическим откатом. Не отключать
основной сервер пользователей ради теста.

Проверки разработки:

```sh
go test ./...
go vet ./cmd/dagami-reserve ./internal/managed
python -m unittest discover -s deployment/reserve -p 'test_*.py'
```

Публичные списки обрабатываются отдельным клиентским режимом без ключа.
Массовая автоматическая загрузка бесплатных адресов в серверный приватный пул
не включена. Для него добавляются оплаченные владельцем выходы через панель.
