# Dagami Agent Proxy — исправления Google, Gemini и DNS (v0.1.0-alpha.2, fix2)

Основа: скачанный GitHub v0.1.0-alpha, опубликованный 15 октября. Скачанный EXE
имеет SHA-256 `7d03b70727768b57fe905b928d31bb13083c6dde395f0215ede0795567594c11`;
это контрольная сумма исходного релиза. GitHub /latest исключает
prerelease и возвращает прежний v2.3.5: здесь использовался список релизов с alpha.
Исходный архив: commit f3bd5a1. Сохранены более поздние проверки активации
из commit 19882e6. LicenseManager, данные активации, профили и журнал ярлыков не менялись.

## Причины и изменения

1. В исходном релизе Smart DNS охватывал только два API Antigravity. GET к
   lh3.googleusercontent.com через выбранный upstream воспроизводил HTTP 502,
   а прямой маршрут через существующий Smart DNS проходил проверку TLS. В исправлении
   один явно заданный маршрут используется для 19 точных имён Google/Antigravity:
   API, вход, OAuth, аватар, статика и зависимости Gemini. Wildcard-маршрутов нет.
   Флажок Smart DNS сохраняет управление этим режимом; при выключении весь трафик
   по-прежнему проходит через выбранный upstream. Серверы не перенастраивались.
2. Gemini.exe/GeminiAppLauncher.exe ранее получали только HTTP_PROXY и аналоги.
   Добавлены параметры Chromium, WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS и
   QTWEBENGINE_CHROMIUM_FLAGS ([WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/webview-features-flags), [Qt](https://doc.qt.io/qt-6/qtwebengine-debugging.html)). Если рядом с лаунчером есть Gemini.exe, запускается
   основной EXE. Сохраняются обычный профиль аккаунта и имеющиеся аргументы WebView.
   Перед первой проксируемой сессией приложение должно быть полностью закрыто.
3. Сессия учитывает дочерние процессы [Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) после выхода лаунчера. Запуск,
   повторное открытие, счётчик сессий и остановка используют принадлежащие сессии
   процессы. Для процессов, созданных внешним системным брокером вне Job Object,
   такой учёт не гарантируется; приложение Gemini на машине заявителя не запускалось.
4. В «Подключение» добавлена явная кнопка «Записать DNS в систему…». Окно записи
   принимает DNS из настроек, разрешает имя в IP, показывает активные адаптеры,
   кнопку подтверждения записи, результат и восстановление. Запись требует UAC.
   NRPT отключён по умолчанию: конфликтующий набор правил больше не блокирует
   обычную запись DNS адаптеров. Откат адаптеров работает и без NRPT-командлета.
   Сохранены исходный DHCP/статический режим, IPv4/IPv6, резервная копия и защита
   от перезаписи чужих изменений. В NRPT-набор добавлены адреса входа и аватара Google.
5. В главном окне отдельно показаны Smart DNS локального моста и системный DNS.
   Для системного DNS проверяются сохранённая операция и текущие адреса адаптеров.
   Диагностика Antigravity теперь проверяет также адреса аккаунта, аватара и Gemini;
   счётчики маршрутов включают все 19 имён. Реальные коды OAuth не повторяются.

## Проверки

- 44 Python-теста: профили, IPC, туннель, восстановление, переносимые ярлыки, лицензия.
- 29 проверок Google/Gemini: точные маршруты, отсутствие wildcard, параметры браузера,
  сохранение профиля и реальный дочерний процесс после завершения родителя.
- 33 проверки EOF, восстановления CONNECT и отсутствия повторной отправки запросов.
- 24 проверки входа, профиля, редактирования журналов и реального сокетного relay.
- 13 проверок DNS UI/валидации/встроенного модуля; 204 проверки компактной верстки.
- 44 PowerShell-проверки DNS с подменой сетевых операций: DHCP, IPv4/IPv6, NRPT,
  конфликты, откат, работа без NRPT. Системный DNS этой машины тестами не изменялся.
- На сборке fix1, сетевые изменения которой сохранены в fix2: 14 реальных HTTPS-проверок с проверкой сертификатов через
  выбранный маршрут. OAuth POST с вымышленными данными — HTTP 401; вход — 302;
  корневой URL хоста аватара — 400 без 502; Gemini — 200; API без токена — 401/404.
  Ответы 4xx здесь ожидаемы для диагностических URL без аккаунта. Полный журнал ниже.

## Повторная проверка у пользователя

Завершите старый менеджер через «Выход» в трее, полностью закройте Antigravity/Gemini
и распакуйте ZIP релиза. Сохраните прежний EXE и замените его новым `DagamiAgentProxy.exe`
по прежнему пути: тогда обычные пропатченные ярлыки будут использовать исправление.
Профили и журнал ярлыков хранятся отдельно; удалять их при обновлении не нужно.
Сверьте SHA-256 скачанных файлов с `SHA256SUMS.txt`.
Включите Smart DNS, повторите свежий вход. Для записи DNS в Windows отдельно откройте
«Подключение → Записать DNS в систему…», выберите адаптеры и подтвердите UAC.

Транспорт исправлен и проверен. Успешный вход реального аккаунта, загрузка его аватара,
модели и сообщения требуют проверки в приложениях. Официальный Gemini.exe заявителя
недоступен локально: совместимость его конкретной версии ещё не подтверждена.
Дистрибутив публикуется только в GitHub. Серверная конфигурация не изменялась.
