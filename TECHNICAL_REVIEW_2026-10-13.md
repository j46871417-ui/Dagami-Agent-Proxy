**Почему GUI не запускается**

Есть две разные точки входа, и результаты для них различаются.

| Точка входа | Что установлено | Уровень подтверждения |
|---|---|---|
| `python devproxy_gui.py` | Конструктор вызывает `_refresh_profiles()`, который обращается к отсутствующему `ProxyProfile.list_profiles()`. Возникает `AttributeError` до `mainloop()`. | Ошибка воспроизведена вызовом метода; отсутствие API проверено непосредственно в классах. |
| `devproxy.exe` | В диагностическом .NET Framework процессе `HttpInitialize` возвращает `5`, `HttpListener.IsSupported` равен `false`, а конструктор `HttpListener` бросает `PlatformNotSupportedException`. `StartHttpServer()` скрывает исключения; форма намеренно невидима. | Подтверждено для текущего контекста выполнения. Это не доказывает, что обычный запуск из Проводника вне среды Codex имеет те же ограничения. |
| C# GUI через диагностический .NET-хост | Конструктор из существующей сборки успешно создаёт UI-сервер и запускает Edge. Страница `/` и `/api/targets` возвращают HTTP 200. Внешний прокси был отключён только в памяти. | Подтверждено запуском и наличием окна Edge с заголовком DevProxy. |

Код `5` означает `ERROR_ACCESS_DENIED`, а не отсутствие поддержки HTTP в установленной Windows: [Microsoft — System Error Codes](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--0-499-). В системе установлен .NET Framework 4.8.1; `--help` существующей сборки выполняется. Переустановка .NET или отключение защиты Windows из этих результатов не следует.

Для Windows воспроизведён дефект обработки отказа UI-хоста: `new HttpListener()` → исключение → пустой `catch` → продолжение конструктора с невидимой формой и неработающим адресом UI. Одновременно запись в журнал из диагностического EXE получила `UnauthorizedAccessException`, которая также подавляется. Поэтому у пользователя может не быть ни окна, ни объяснения. Точный источник ограничений токена/политики запуска вне диагностической среды не установлен.

В историческом журнале 12 октября отдельно подтверждён конфликт портов: UI занимал `53129` и `53130`, а прокси-мост пытался использовать тот же диапазон. Этот конфликт повреждает маршрутизацию, но сам по себе не доказывает причину отсутствия окна Edge.

Исправление старта: согласовать Python GUI с существующим API; в C# проверять успешность UI-хоста до открытия браузера, показывать исходное исключение и иметь работающий канал диагностики. Для ограниченных процессов нужен UI-хост, не зависящий от недоступного HTTP.sys, либо явно документированные требования к его запуску. Не следует компенсировать эту ошибку отключением TLS или постоянным запуском всего менеджера с правами администратора.
