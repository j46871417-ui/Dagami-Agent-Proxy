# Обновления GitHub — Windows up5, 16 октября 2026

Версия: `v0.1.0-alpha.5`, FileVersion `0.1.0.5`.
Режим по запросу пользователя: автоматическая проверка, установка только по кнопке.
Публикация: [GitHub v0.1.0-alpha.5](https://github.com/j46871417-ui/Dagami-Agent-Proxy/releases/tag/v0.1.0-alpha.5).
CLI cli4 и диагностика userinfo diag3 включены в эту версию.

## Пользовательский сценарий

1. Первый раз установить up5 вручную: завершить прежний менеджер через трей,
   сохранить старые EXE и заменить ОБА файла по прежнему пути файлами одного архива:
   `DagamiAgentProxy.exe` и `dagami-proxy.exe`. Профили и активацию не удалять.
2. В левом нижнем углу — «Обновления» и установленный тег. Фоновая проверка работает
   при запуске и раз в 6 часов, использует кеш и не скачивает/не устанавливает версии сама.
   Её можно отключить. Предварительные версии включены по умолчанию для alpha-проекта.
3. Открыть «Обновления»: видны установленная/доступная версии, описание релиза,
   последняя операция. «Проверить» выполняет явный повторный запрос GitHub.
4. «Скачать и установить» загружает и проверяет выбранный релиз. Если работают
   проксируемые приложения, CLI или туннель браузера входа, файлы остаются скачанными;
   установка не выполняется. После завершения работы нажать «Установить» повторно.
5. Помощник подтверждает готовность, ждёт завершения старого менеджера, заменяет
   пару и перезапускает GUI. Работающие программы принудительно не завершаются.

CLI: `dagami-proxy.exe update check` и `update download`. Установка — через GUI.
Клиент Windows Forms/.NET; Python GUI/CLI для Linux/macOS этим обновлятором не меняются.

## Источник и сеть

Только публичный API `j46871417-ui/Dagami-Agent-Proxy`, без GitHub-токена.
Используется список релизов, поскольку `/latest` не включает alpha/prerelease.
Версии сравниваются как SemVer; alpha.10 новее alpha.2, stable новее alpha той же базы.
Legacy-релизы DevProxy без брендированного Windows-пакета не выбираются.

Сначала прямой HTTPS, при сетевом отказе — временный loopback-мост с выбранным
HTTP/HTTPS-прокси. Настройки маршрутов остальных приложений не меняются. Если доступ
идёт через прокси с белым списком назначений, разрешить `api.github.com`, `github.com`,
`release-assets.githubusercontent.com`, при необходимости `objects.githubusercontent.com`.
TLS проверяется. Только GET, максимум шесть разрешённых HTTPS-перенаправлений,
ограничение размера ответа/файла и таймауты. OAuth/аккаунты обновлятор не использует.

[GitHub REST: releases и digest assets](https://docs.github.com/en/rest/releases/releases).

## Проверка пакета

Поддержаны отдельные `DagamiAgentProxy.exe` + `dagami-proxy.exe` или Windows ZIP.
Варианты ZIP: `Dagami-Agent-Proxy-TAG-windows.zip`, `Dagami-Agent-Proxy-windows-x64.zip`,
`Dagami-Agent-Proxy-windows.zip`. Предпочтителен первый, где TAG — точный тег релиза.

Для каждого скачиваемого файла необходим API digest `sha256:…`; проверяются размер
и SHA-256. Для ZIP дополнительно нужны в корне оба EXE и `SHA256-native.json` с
контрольными суммами. Извлекаются только два EXE; прочие пути архива не записываются.
Проверяются ProductName, одинаковая FileVersion, роль GUI/console и соответствие
ProductVersion тегу. Поддержан legacy-формат alpha.2 с точной revision FileVersion.
В последующих релизах AssemblyInformationalVersion должен содержать точный SemVer.

SHA-256 обеспечивает проверку целостности относительно GitHub API; это не подпись
издателя. Доверие к источнику основано на TLS и указанном репозитории GitHub.

## Установка, блокировки и восстановление

Профили, ключ активации, системный DNS, backend Antigravity и конфигурации приложений
не входят в набор заменяемых файлов. GUI ставится по прежнему пути, включая прежнее
имя EXE; CLI — рядом. Это сохраняет существующие обычные ярлыки.

Настройки проверки: `%LOCALAPPDATA%\DagamiAgentProxy\updates\settings.json`.
Кеш и план помощника защищены DPAPI CurrentUser. Каждая попытка имеет отдельный
каталог staging и свои маркеры ready/cancel, чтобы повтор не видел старую готовность.

Устанавливающий помощник — копия CLI той же установленной версии. Нет внешних
скачанных install-скриптов или исполняемых инструкций из release notes. При отсутствии
прав записи Windows запрашивает UAC; смена учётной записи не обходит DPAPI.
Проверка UAC в Program Files на контрольной машине не выполнялась: проверена обычная
переносимая установка в пользовательский каталог.

Помощник проверяет PID и время старта родителя, ждёт его выхода без kill, получает
эксклюзивную блокировку активности. GUI и новые CLI удерживают общую блокировку;
CLI имеет отдельную регистрацию. Старые CLI-запускатели дополнительно ищутся по
собственному каталогу, а блокировка файлов препятствует небезопасной перезаписи.
Счётчик моста охватывает всю жизнь обеих relay-нитей, а не только обработку CONNECT.

Перед заменой сохраняются прежние GUI/CLI. На момент установки снова сверяются
скачанные хеши и снимок установленных файлов. После записи проверяются оба хеша.
При сбое замены второй части или обновления CLI-запускателей пара откатывается.
Чужие поздние изменения не перезаписываются; при невозможности отката показывается
путь резервной копии. Существующие CLI-запускатели и их DPAPI-журнал обновляются
транзакционно, оригинальные CLI не изменяются.

Результат: `updates/last-result.json`; его сообщение видно в окне обновлений.
Копии пары — `updates/staged/.../backup-*`, копии CLI-запускателей — соседний
`cli-backup`. Для ручного отката завершить менеджер/CLI, восстановить оба EXE;
если обновлялись CLI-запускатели, восстановить их файлы и state.dat из cli-backup
в `%LOCALAPPDATA%\DagamiAgentProxy\cli`. Перед ручным откатом сохранить текущие файлы.

## Проверки

Финальный прогон: 70 updater-проверок, 37 CLI, 31 обычных GUI-ярлыков, 30 userinfo,
33 EOF/no replay, 24 входа/реального relay, 29 Google/Gemini, 204 UI. Всего 458.
Проверены плохие URL/версии/хеши, повреждённый DPAPI-план, ZIP-only релиз и отсутствие
Zip Slip, реальный File.Replace, блокировка CLI-файла и откат GUI, чужое изменение,
обновление временных CLI-запускателей и запрет установки при живом туннеле.

Отдельный helper запускался настоящим процессом с временной установкой: успех,
занятый CLI, отмена, ожидание выхода родителя. Тестовый CLI-запускатель во время
эксклюзивной установки вернул exit 1 и stderr без GUI-диалога. История результата
обновления пользователя после smoke-теста восстановлена.

Реальный публичный feed GitHub нашёл alpha.2. Его ZIP скачан через HTTPS-редирект,
SHA-256 архива и обоих EXE проверены; GUI/CLI внутри валидированы. Alpha.2 не
устанавливалась поверх локальной alpha.5. Пользовательские PATH/активация/профили
и реальные установленные программы тестами не заменялись.

В одном промежуточном прогоне был таймаут локального сокетного теста NativeLoginChecks.
Повтор с трассировкой передал 262144 байта в обе стороны; финальный полный прогон
прошёл. Пользовательский HTTP 502 userinfo этим не объявляется исправленным.
На Linux/macOS и в сценарии UAC повышение прав не проверялись.
