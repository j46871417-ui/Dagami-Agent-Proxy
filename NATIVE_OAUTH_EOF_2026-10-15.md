## Наблюдения

Antigravity сообщил: POST oauth2.googleapis.com/token: unexpected EOF.
Через работающий и отдельный нативные мосты воспроизведён upstream EOF
до получения HTTP-ответа на CONNECT. Прямой запрос к тому же upstream также
однажды получил такой EOF. В других попытках получен CONNECT 200 и полный
HTTP 401 invalid_client на POST /token с вымышленными code/client_id.
Байты CONNECT моста и прямого клиента сравнены в памяти: совпадают.
Проверка TCP_NODELAY не показала устойчивой причинной зависимости;
параметр не менялся. Корневая причина нестабильности upstream не установлена.

## Изменения

- До трёх попыток CONNECT только при EOF до полного ответа, с короткой паузой.
  После подтверждения туннеля нет повторов TLS/application data/OAuth POST.
- Отказ upstream и исчерпание попыток дают HTTP 502 вместо молчаливого EOF.
  Статус разбирается строго; 2000 не принимается за 200; неполный заголовок
  не принимается за успешный ответ. После открытия туннеля HTTP 502 в TLS не вставляется.
- Журнал: correlation ID, домен/порт, маршрут, этап, статус CONNECT, попытки,
  длительность, объём по направлениям, тип ошибки и SocketErrorCode.
  Тела, заголовки, OAuth-ссылки/коды и proxy credentials не записываются.
- HTTPS upstream использует TLS 1.2 с проверкой сертификата и отзыва.
- Повторный запуск поверх работающего Antigravity блокируется с объяснением:
  существующий процесс не получает новое окружение и параметры прокси.
- Унаследованные AGY_PROXY_URL/agy_proxy_url приведены к тому же локальному мосту.
- Выход процесса запуска из ярлыка больше не закрывает мост. У ярлыковой сессии
  теперь есть полноценное окно и трей. Закрытие окна скрывает его; «Выход»
  в трее завершает процесс. Старый скрытый shortcut-host без трея не используется.
- «Диагностика маршрута» теперь делает безопасный POST /token с фиктивными
  данными и объясняет ожидаемый HTTP 400/401.

## Проверки

- 33 новых проверки NativeEofChecks: два EOF -> успех, лимит повторов,
  отсутствие повторов после 403/неправильного ответа, буферизованные данные
  передаются ровно после успешного CONNECT, half-close, 502, запрет второй сессии.
- 24 существующие NativeLoginChecks пройдены на новой сборке.
- NativeIntegrationChecks пройдены: сигнатуры/backup/откат/DNS scope только
  на временных фикстурах. Установленный клиент эти проверки не изменяли.
- Windows PowerShell/.NET Framework: окно отрисовано, закрытие скрывает в трей,
  listener продолжает принимать соединения, восстановление окна работает,
  shortcut-конструктор создаёт трей и полное окно без запуска Antigravity.
- Реальная сеть: POST /token -> HTTP 401 invalid_client, оба cloudcode API ->
  HTTP 401 без токена, строгая проверка сертификатов; TLS 1.3 + HTTP/1.1 и HTTP/2
  через новый нативный мост получили полные ответы с END_STREAM.
  Также зафиксирована неудачная серия из трёх CONNECT EOF до успешных серий.

## Ограничения и проверка пользователем

Интерактивный OAuth и ответ модели не подтверждены. Исправлены конкретные
дефекты и добавлена диагностика; любой EOF устранённым не объявляется.
Повторы CONNECT не исправят постоянную недоступность upstream.
Для проверки полностью закрыть прежний Antigravity, запустить его через
новый Desktop/DevProxy.exe и начать свежий вход. Старый код входа не повторять.
После ошибки смотреть последний Bridge ID, CONNECT status/phase и объём
направлений в APPDATA/devproxy/devproxy.log.
