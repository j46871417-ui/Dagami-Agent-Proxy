# Userinfo Bad Gateway — диагностика diag3, 16 октября 2026

## Наблюдение и границы

У пользователя на alpha.2/fix2 после OAuth возникает:
`GET https://www.googleapis.com/oauth2/v2/userinfo: Bad Gateway`.
Этот хост уже был в точном Smart DNS-списке fix2, но в прежние 14 HTTPS-проверок
сам endpoint не входил. Проверки токена и аватара не доказывали доступность userinfo.

На контрольной машине опубликованный fix2 и новая diag3 возвращают ожидаемый
HTTP 401 без токена для `/oauth2/v2/userinfo` и `/oauth2/v3/userinfo` через оба
маршрута: Smart DNS и настроенный upstream. TLS-сертификаты проверены.
CLI `diagnose login` на diag3 также вернул ожидаемый 401.
Это не успешный вход аккаунта. Причина HTTP 502 на проблемном ПК пока не установлена;
исправление пользовательского входа не заявляется. Серверы не перенастраивались.

## Что изменено

- «Antigravity → Проверить» выполняет точный GET `/oauth2/v2/userinfo` без токена.
- В отчёте показаны версия/FileVersion, порт проверяемого моста и режим Smart DNS.
- HTTP 5xx, 407, 429 явно считаются ошибками проверки даже при успешном TLS.
  Для userinfo ожидается 401; неожиданные 200/302/403/404 не объявляются успехом.
- При ошибке userinfo сравнивается альтернативный маршрут через отдельный временный
  мост. Настройки и работающий мост не меняются, запрос пользователя не повторяется.
- В журнале при DNS-сбое сохраняются безопасное имя назначения и этап
  `smart-dns-resolve` / `smart-dns-connect` вместо общего `client-header`.
- CLI: `dagami-proxy.exe diagnose login`. Команда добавлена в --help.

Проверено: 30 проверок userinfo/статусов/реальных отказов CONNECT/сравнения маршрутов;
33 EOF/отсутствия replay; 24 входа/relay; 29 Google/Gemini; 204 UI. Всего 320.
Реальные HTTPS-запросы diag3: четыре ожидаемых 401 (два пути × два маршрута).
Действующие аккаунты, токены, реальные OAuth-коды и backend Antigravity не читались
и не менялись. Работающие приложения не завершались. Данные активации сохранены.

## Проверка на проблемном компьютере

1. Для GUI: закрыть Antigravity и завершить прежний менеджер через «Выход» в трее.
   Сохранить прежние EXE и заменить оба файла из одного архива:
   `DagamiAgentProxy.exe` и `dagami-proxy.exe` по прежнему пути.
   Запустить v0.1.0-alpha.5, открыть «Antigravity → Проверить», скопировать отчёт.
2. Без замены GUI: распаковать диагностический ZIP и запустить
   `Собрать отчёт.cmd`. Он выполняет CLI-проверку через отдельный мост с сохранёнными
   настройками; работающая GUI-сессия не изменяется. `userinfo-report.txt`
   относится к новому диагностическому мосту, не доказывает маршрут старой GUI-сессии.
3. Для дальнейшего исправления нужны этот отчёт и журнал вокруг реального сбоя входа.
   Перед передачей удалить пароли, токены, ссылки входа и персональные данные.
